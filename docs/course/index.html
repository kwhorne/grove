The Perfect Setup

Local development with Grove, from a machine with nothing on it to a team that shares one environment. Fourteen chapters that build the setup you would have designed yourself if you had ever had a free week — and explain why each piece is there before showing which command puts it in place.

Who this is for

Anyone who runs web projects on a Mac and has felt the weight of their own machine. You will get the most from it if you work with PHP — Laravel, WordPress, plain PHP — but the DNS, the certificates, the service supervision and the request timeline are the same whatever is behind them.

The running example is Freddy, a small notes app. Substitute your own project everywhere you see his; nothing here depends on how he was built.

What you need

A Mac on Apple silicon or Intel, and administrator access for two commands in chapter 2. Linux support is in beta and the commands are the same. Nothing else is required: Grove brings its own PHP, Node, databases and mail server, so Homebrew is optional and Herd and Valet are replaceable — chapter 7 removes them.

How to read it

Every chapter is built the same way: the problem (why this exists at all), the hard way (what you would do without it, and why that goes wrong), then the work. The order matters — chapter 13 makes your environment reproducible, and it can only do that because chapters 3 to 8 decided what there is to reproduce.

The chapters

  1. 1. What a Local Environment Actually Is — The five jobs every dev machine does, why they are usually five unrelated tools, and what changes when one process owns them.
  2. 2. Install, and What Needs Root — Two privileged commands, what each one writes, and why the daemon that serves your sites is not root at all.
  3. 3. A Folder Becomes a Site — Park, link, and the reason a real DNS resolver beats an /etc/hosts line every single time.
  4. 4. A Padlock That Means Something — Why localhost needs HTTPS now, one command that provides it, and the constraint that makes a local CA safe.
  5. 5. PHP, Exactly the One You Need — Several versions at once, pinned per site, and an honest account of which extensions are there and which are not.
  6. 6. The Rest of the Stack — Databases, Redis and a mail-catcher Grove installs itself — and one command that writes the .env block for them.
  7. 7. The Terminal Follows the Project — Shims that make php, composer and node resolve per project — and the chapter where Herd and Valet come off.
  8. 8. The Processes a Project Needs — Queue workers, Vite and schedulers started and supervised together — and the one command you must not put in the list.
  9. 9. Before the Scary Migration — Snapshots and one-command restores — what it buys you, and why owning the database is what makes it possible.
  10. 10. Seeing the Request — A timeline of every request, the queries it caused, and a replay button — from the process that served it.
  11. 11. Letting the Outside In — A public URL for a local site, and a webhook you can deliver again without going back to Stripe.
  12. 12. A Breakpoint Instead of a Dump — Xdebug on demand, the honest reason static builds cannot load it, and how to get it working anyway.
  13. 13. Reproducible, in the Repository — grove.toml: the environment described where the code lives, so a clone becomes a running setup with one command.
  14. 14. The Team, and Keeping It — Secrets shared end-to-end encrypted, an assistant that can see your environment, and the habits that stop it rotting.
